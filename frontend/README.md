# Frontend – Enterprise Structured Ingestion Firewall

## Overview

The frontend is a lightweight, responsive web interface built with HTML, CSS, and vanilla JavaScript. It allows users to submit natural-language messages and view the structured JSON generated by the backend.

The interface communicates with the FastAPI backend using the browser Fetch API. It displays request status, handles connection and API errors, and provides a copy-to-clipboard option for successful JSON responses.

## Technology Stack

- **HTML5** – Page structure and interface components
- **CSS3** – Layout, styling, and visual presentation
- **JavaScript** – User interactions and API communication
- **Fetch API** – HTTP requests to the backend
- **Clipboard API** – Copying JSON results

No frontend framework or package manager is required.

## Features

- Clean interface for entering messages.
- Character counter with a 5,000-character limit.
- Quick example buttons for common message categories.
- Integration with the FastAPI analysis endpoint.
- Loading states during message analysis.
- Live status messages for requests and connection failures.
- Formatted JSON output.
- Copy-to-clipboard functionality.
- Validation status banner.
- Basic backend availability indicator.
- Error messages for failed requests and unsuccessful responses.

## How It Works

1. The user enters a message or selects a quick example.
2. JavaScript checks that the message is not empty.
3. The frontend sends a JSON request to the backend.
4. The backend processes the message and returns structured data.
5. The frontend displays the JSON response and updates the status banner.
6. The user can copy the result to the clipboard.

## Backend Integration

The frontend is configured to use the local API:

```javascript
const API_URL = "http://127.0.0.1:8000";
```

The analysis request is sent to:

```text
POST http://127.0.0.1:8000/api/analyze
```

Example request:

```json
{
  "message": "My payment was deducted twice."
}
```

The response is formatted and displayed in the JSON output panel.

The frontend also checks the backend's OpenAPI endpoint to update the connection indicator.

## Setup and Run

### Prerequisites

- A modern web browser
- Python 3.10 or later, for the simple local static server
- The backend configured and running

### 1. Start the backend

Follow the instructions in [Backend README](../backend/README.md).

The backend should be accessible at:

`http://127.0.0.1:8000`

### 2. Start the frontend

Open a new terminal and navigate to the frontend directory:

```bash
cd frontend
python -m http.server 5500
```

### 3. Open the application

Visit:

`http://127.0.0.1:5500`

Enter a message and select **Analyze Message** to view the response.

Keep the frontend and backend terminals running while testing the application.

## Error Handling

The interface handles several common situations:

- **Empty input:** Prompts the user to enter a message.
- **Loading:** Disables the submit button while a request is in progress.
- **API errors:** Displays the returned error information.
- **Connection failures:** Advises the user to check whether the backend is running.
- **Successful response:** Displays formatted JSON and enables the copy button.
- **Clipboard errors:** Allows the user to select and copy the JSON manually.

## Troubleshooting

### Backend offline

Ensure the backend is running at `http://127.0.0.1:8000`.

### Failed API request

Check the backend terminal for errors. Confirm that the Groq API key and model configuration are valid.

### CORS error

The backend currently enables CORS for local development. If the frontend is served from another origin, verify the backend's CORS configuration and restrict it to the required frontend origin when deploying.

### JSON output is not displayed

Check the browser developer console and the backend logs for errors.

### Copy JSON does not work

Clipboard access can depend on browser permissions and the page's security context. Use the local HTTP server and copy the text manually if needed.
